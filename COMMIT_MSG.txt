feat(smart-mail): 0.2.0 — same-thread reply continuation, archive restore, quieter rotated logs

Mail is now a conversation entry point, not a notification feed.

Thread continuation
- Every outgoing message records its Message-ID against a thread tag and carries
  `[dsh-xxxx]` in the subject plus `X-DSH-Session` / `In-Reply-To` / `References`.
- An inbound reply resolves back to its session in a fixed order: References /
  In-Reply-To matched against our own outgoing ids, then the X-DSH-Session header,
  then the subject tag (tolerant of `Re:`/`回复:`, case, a dropped bracket, and a
  re-encoded subject). Only tags in our own table can bind; anything else starts
  a new thread.
- A reply into a running session interrupts it: `prompt(mode:'steer')` when the
  Host accepts it, otherwise `queue` + `cancel({sessionId})` (which keeps the
  inbox, so the queued reply is picked up immediately). The log states which path
  was taken — no hard interrupt is ever claimed when one did not happen.

Archived sessions
- `ArchivedSessionGate` rejects every step of an archived session, so delivery
  restores it first via `workspaceRegistry.unarchiveSession()` — the same durable
  write the Host's `workspace/unarchiveSession` Remote uses. When that method is
  absent, the equivalent `enqueueOperation`/`requireState`/`setState` write drops
  the id from `archivedSessionIds`. The path used is recorded per delivery; a
  session that cannot be restored fails loudly instead of silently starting a
  new conversation.

Logging (noise down, detail kept, growth bounded)
- `plugin-start` records a digest (version, allowFrom count/sample, interval,
  prompt length); the full config is written only when it actually changed, with
  `changedFields`, `before`, and `after`.
- `mail-seen` is one aggregate line per poll round (counts, reason set, top
  senders, and each sender's allowlist decision) instead of one line per mail.
- `mail-wake` keeps full detail on success and failure, including from/to/cc,
  subject, Message-ID, In-Reply-To, reference count, thread tag, resolution path,
  route, session id, delivery mode, and the complete error.
- Rotation: split at `logMaxBytes` (default 2 MiB) or across a calendar day,
  pruned to `logKeepDays` (7) and `logKeepFiles` (20); reads span the current
  file plus archives, so the panel keeps its history. Policy is configurable in
  the panel and documented in the README.

Also
- IMAP now honours `imap.tls` (a clear socket is only for local tests) and fetches
  an explicit header field list with BODY.PEEK, so polling never marks mail read.
- Duplicate detection is by Message-ID (`messages.json`), not just UID, so a
  re-poll or a UIDVALIDITY reset cannot run the same mail twice.
- Panel gains thread-continuation switches, rotation settings, log health, and a
  thread→session table; the activity log formatter understands every event kind.

Verified against a real DSH host in an isolated profile with a scripted LLM
provider, a fake IMAP server, and a fake SMTP server: 13/13 integration checks
(new thread, References continuation, subject-tag fallback, interrupt-while-
running, archived-session restore, new-session for unrelated mail, no wake for
non-whitelisted senders, duplicate skip, restart persistence, rotation, config
change once) plus 24 offline and 14 session-bridge unit checks.
